# Agent Mesh OS Architecture

## Core Design Principles

### 1. Orchestration: Durable Execution over Task Queues
We replaced basic `asyncio` or `Celery/Redis` implementations with **DBOS**, a durable execution engine that runs natively inside Python backed by Postgres (or SQLite for dev).

**Why?** The 3-pass Agent Loop (Plan -> Execute -> Review) requires human-in-the-loop approvals. With DBOS `DBOS.recv("approval", timeout_seconds=86400)`, the python workflow suspends securely for 24 hours without tying up CPU or RAM. If the container crashes, DBOS replays the journal and resumes *exactly* at the approval gate. 
*Note:* A Dead Letter Queue (DLQ) acts as a safety valve. If the workflow fatally errors, the payload is journaled to a `dlq_events` table for later analysis.

### 2. Event Bus: Real-Time Memory
All agents broadcast internal state (`planning`, `executing`, `blocked`) to a shared event bus (`events.py`). This powers the front-end dashboard dynamically using Server-Sent Events (SSE). 

### 3. Isolation: E2B Sandboxes
Standard containers (Docker) share the host kernel and are insufficient boundaries for unvetted, LLM-generated execution. We mandate the use of `e2b_code_interpreter` (Firecracker microVMs). 
Code generated by `CommitGuardAgent` during the `Execute` pass is evaluated securely in a remote Firecracker VM.

### 4. Observability: OpenLLMetry
For detailed step tracing, token counting, and cost-control, the app utilizes `traceloop-sdk`. Traceloop exports standard OpenTelemetry traces to Langfuse or compatible endpoints to trace the `BaseAgent` actions without massive proprietary lock-in. 

## Flow

1. **User** invokes `/api/run`.
2. **DBOS Workflow** (`agent_loop`) spawns `CommitGuardAgent`.
3. Agent invokes `plan()`, storing state via `update_status`.
4. Agent invokes `request_approval()`. DBOS suspends.
5. **Dashboard** visualizes the suspended task (UI badge: `Blocked`).
6. **User** approves in dashboard. DBOS resumes.
7. Agent invokes `execute()` which spins up a temporary **E2B Firecracker Sandbox** to run code.
8. Agent performs `review()`.
9. The workflow completes, updating DBOS tables and closing the loop.
