# Agent Mesh OS Architecture

## Core Design Principles

### 1. Orchestration: Durable Execution over Task Queues

We replaced basic `asyncio` or `Celery/Redis` implementations with **DBOS**, a durable execution engine that runs natively inside Python backed by Postgres (or SQLite for dev).

**Why?** The 3-pass Agent Loop (Plan -> Execute -> Review) requires human-in-the-loop approvals. With DBOS `DBOS.recv("approval", timeout_seconds=86400)`, the python workflow suspends securely for 24 hours without tying up CPU or RAM. If the container crashes, DBOS replays the journal and resumes _exactly_ at the approval gate.
_Note:_ A Dead Letter Queue (DLQ) acts as a safety valve. If the workflow fatally errors, the payload is journaled to a `dlq_events` table for later analysis.

### 2. Event Bus: Real-Time Memory

All agents broadcast internal state (`planning`, `executing`, `blocked`) to a shared event bus (`events.py`). This powers the front-end dashboard dynamically using Server-Sent Events (SSE).

### 3. Isolation: E2B Sandboxes

Standard containers (Docker) share the host kernel and are insufficient boundaries for unvetted, LLM-generated execution. We mandate the use of `e2b_code_interpreter` (Firecracker microVMs).
Code generated by `CommitGuardAgent` during the `Execute` pass is evaluated securely in a remote Firecracker VM.

### 4. Observability: OpenLLMetry

For detailed step tracing, token counting, and cost-control, the app utilizes `traceloop-sdk`. Traceloop exports standard OpenTelemetry traces to Langfuse or compatible endpoints to trace the `BaseAgent` actions without massive proprietary lock-in.

## Advanced Agent Architectures

We incorporate patterns from best-in-class open-source agent frameworks:

### 1. Self-Improving Skill Store (Hermes pattern)

Agents now feature a **Self-Improvement Loop**. When a high-level goal is successfully met (Review pass: `True`), the successful execution path (actions + observations) is extracted and codified into a permanent **Markdown Skill** file (`~/.agent_mesh/skills/`).
Relevant skills are automatically injected into the context of future runs, allowing agents to "remember" successful strategies and avoid redundant reasoning.

### 2. Code-Native Tool Use (smolagents / ml-intern pattern)

Advanced agents like `MLInternAgent` utilize **Code-Native tool calling**. Instead of just invoking static JSON functions, the agent writes and executes Python snippets in a secure **E2B Sandbox**. This allows for complex data processing, multi-step tool orchestration, and algorithmic reasoning within a single "thought" step.

### 3. Orchestration & Brain (Hermes / CrewAI pattern)

The `HermesAgent` acts as the **Brain of the Mesh**. It focuses on high-level planning and **Proactive Delegation**. It can spawn and monitor specialized subagents (CommitGuard, Research, Marketing) to handle parallel workstreams, mimicking a role-based human organization.
